# 小红书版本

> 小红书**不是搬运**——它要的是图片为主的短内容。下面这份是**重写**过的，配图脚本才是主角。
> 建议先发一版看数据，标题可以换着试（小红书标题权重很高）。

```
姐妹们（和兄弟们），分享一个我最近做的小东西

一部分功能在云上，手机插在本地电脑上

两边都要看日志、出结论

我干了什么？
在云上跑一遍 → 复制
切到本地再跑一遍 → 复制
两条对着看 → 对不上 → 再来一轮

来回几十趟

那天结束我算了一下
真正写代码不到两小时
剩下的时间我都在当两台机器之间的快递员🥲

最荒诞的是——
两边终端里都跑着 AI agent
它们本来就会读日志会分析
我夹在两个会聊天的 AI 中间，手抄它们的对话

所以我就想
为啥不让它俩自己聊？

做出来的东西长这样👇

现在我要问那边什么
直接说一句就行：
「问一下电脑那边，构建过了没」

① 两台机器各装一次

这东西不是给所有人用的
两台机器在同一个局域网、都开着 SSH 的话
直接 SSH 更快，别折腾

但如果你也经常在两台机器之间当快递员
可以看看👀
```

## 配图脚本（这才是小红书的重点）

**8 张图，顺序如下：**

| # | 图 | 内容 | 备注 |
|---|---|---|---|
| **1 封面** | 大字报 | 黑底白字，一句：**「我让两个 AI 自己联调，中间没我事了」** 副标题：`程序员最该自动化掉的，是你自己` | **最重要**。字要大，别用花哨字体 |
| 2 | 场景图 | 手机上 / 两个终端并排的截图，加箭头标注"云上" "本地" | 不用精致，真实感更重要 |
| 3 | 痛点图 | 手绘感：中间一个人，两边各一台电脑，箭头来回。标注「人肉快递员」 | 这张决定共情 |
| 4 | 关键句 | 纯文字：**「两边终端里都跑着 AI，我却在手抄它们的对话」** | 转折点 |
| 5 | 效果图 | 终端截图：问一句 → 自动答复 | **最需要真截图**，别 P |
| 6 | 三步图 | ①装 ②出名片 ③贴名片，三格 | 简洁 |
| 7 | 优势图 | 「不用公网 IP / 端口映射 / 内网穿透 / SSH」四个对勾 | |
| 8 | 收尾 | 纯文字：「什么时候别用」+ 「GitHub 搜 agent-penpal」 | 主动劝退反而涨可信度 |

**做图工具**：封面用「稿定设计」或 Figma，终端截图直接系统截图然后在「截图」工具里加箭头标注就行。

## 几个注意

1. **别在正文放链接** —— 小红书对外链不友好。放「GitHub 搜 agent-penpal」这种文字
2. **封面是 90% 的胜负** —— 花最多时间在图上
3. **别用焦虑话术**（"不会就淘汰"这种）—— 你的受众能识破，而且掉粉
4. **第一波评论要回** —— 有人问"这是什么"，认真答，别只丢链接
