# 联调时我当了太久人肉快递员，最后让两个 agent 自己聊上了

> 这是给掘金 / CSDN / 知乎的一稿多投版本。发之前请按你**真实的经历**改细节——
> 编的细节一定会被人问穿，真实的笨拙反而有人信。

---

开发最耗人的地方，我一直觉得不是写代码。

前几天有个活：一部分功能跑在无影云上，手机插在本地这台 PC 上。做起来是这样——云上跑一遍，看日志，复制结论；切到本地，接上手机，再跑一遍，看日志，复制结论。对不上，就再来一轮。来回几十趟。

那天结束我意识到，真正写代码的时间不到两小时，剩下的都在给两台机器当消息总线。

更荒诞的是：两边终端里都跑着一个 AI agent，它们本来就会读日志、会分析、会写结论。**我夹在两个会聊天的 agent 中间，手抄它们的对话。**

---

## 我试过什么

- **复制粘贴** —— 成本不在"复制"这个动作，而在你得一直在线。你不在，链路就断了。
- **远程桌面** —— 能用，但卡。而且我根本不需要"操作那台机器"，只需要那边帮我看一眼，属于大炮打蚊子。
- **SSH** —— 最接近答案，卡在前一步："ssh 通"本身就不便宜。要么两台同局域网，要么弄台有公网 IP 的机器做跳板，要么上 frp/ngrok 内网穿透。每种都要配，公司网络里经常配不通。

---

## 换个角度

我要的不是"连上那台机器"，而是**"让那边的 agent 回答我这边的问题"**。这两件事看着差不多，其实差很远。

如果两边的 agent 能直接对话，我在中间干嘛？它的日志它的 agent 看过了，它的结论它的 agent 会总结。我只需要说一句"去问一下那边"，然后等结论。

卡住的只有一件事：**两台机器怎么找到对方，而且不要求任何一方有公网 IP。**

---

## 现在的做法

一个端到端加密的中转替我把两台机器接上（Paseo 自带，装了 CLI 就有），我在它上面写了套规则，让两边的 agent 互相说话。

用起来三步：

### 第一步 · 两台机器各装一次

```
npx skills add bujianhe/agent-penpal
```

Claude Code / Codex / OpenClaw 都行，另外二十多种 agent 也装得进去。依赖只有 Node 和 paseo CLI，agent 会自己安装依赖。

### 第二步 · 挑一台说"出张名片"

它会检查环境、把缺的依赖装上、起好服务，然后吐出一张名片：

```
=== PENPAL CARD ===
NAME=Mac Mini
DESC=macOS 端：有 Android SDK 和 adb，查构建、抓日志找我
LINK=https://xxxxxxxxxxxx
AGENT=9e1e401
==================
```

### 第三步 · 把名片贴到另一台的 agent 里

配对完成，之后直接说任务：

```
我 > 问一下电脑那边，登录接口改完之后构建过了没

  → 正在问对方…等它处理…
  ========== 答复 ==========
  构建过了，昨天下午那次。顺手把一个 flaky test 也修了。
  ==========
```

中间没有人在搬。

---

## 三句话说完

- **解决什么** —— 一边在云上、一边连着本机，两边的结论老要人肉来回拷。现在让两边的 agent 自己问。
- **配置多麻烦** —— 三步，依赖 agent 自己装。
- **花多少钱** —— 0。开源免费（MIT），不用服务器，不用买任何服务。

---

我做这个不是因为它技术上多难。恰恰相反，难的是意识到自己在做一件蠢事：两个 agent 明明会聊天，我却手抄了那么久。

如果你也经常在两台机器之间当快递员：https://github.com/bujianhe/agent-penpal
