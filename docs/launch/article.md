# 联调时我当了太久人肉快递员，最后让两个 agent 自己聊上了

> 这是给掘金 / CSDN / V2EX / 知乎的一稿多投版本。发之前请按你**真实的经历**改细节——
> 编的细节一定会被人问穿，真实的笨拙反而有人信。

---

联调最耗人的地方，我一直觉得不是写代码。

前几天有个活：一部分功能跑在无影云上，手机又插在本地这台 PC 上。听起来没什么，做起来是这样——

云上那边要跑一遍，看日志，复制结论；切到本地这边，把手机接上，再跑一遍，看日志，复制结论；然后两条结论对照着看，对不上就再来一轮。

来回几十趟。那天结束的时候我意识到，我写代码的时间可能不到两小时，剩下的时间都在**给两台机器当消息总线**。

更荒诞的是：两边的终端里，都跑着一个 AI agent。它们本来就会读日志、会分析、会写结论。

**我夹在两个会聊天的 agent 中间，手抄它们的对话。**

---

## 我试过什么

反正是几个笨办法：

**复制粘贴。** 一直用，用了很久。问题是它的成本不在"复制"这个动作，而在于**你要一直在线**。你不在，链路就断了。

**开远程桌面。** 能用，但卡。而且大部分时候我根本不需要"操作那台机器"，我只需要**那边帮我看一眼**——用远程桌面是在用大炮打蚊子。

**SSH 上去。** 这个其实最接近答案：一旦 ssh 通了，那边跑什么命令都很方便。

问题在前面那一步——**"ssh 通"本身就不便宜**。要么两台在同一局域网，要么弄台有公网 IP 的机器做跳板，要么上 frp/ngrok 那套内网穿透。每种都要配，而且在公司网络里经常配不通。

那几天我在想的是：**我要的不是"连上那台机器"，我要的是"让那边的 agent 回答我这边的问题"。** 这两件事看起来差不多，其实差很远。

---

## 换个角度

如果两台机器上的 agent 能直接对话，那我在中间干嘛？

- 我不需要看到它的日志 —— 它的 agent 看过了
- 我不需要理解它的结论 —— 它的 agent 会总结
- 我甚至不需要知道"要查什么" —— 我这边的 agent 知道，它自己会问

我需要的只有一件事：**在我这边说一句"去问一下那边"，然后等结论。**

真正卡住的地方只有两个：

**第一，两台机器怎么找到对方？** 我一开始就说了，我不想要公网 IP、不想配隧道。那能不能有个现成的东西替我打通？

**第二，那边凭什么信我？** 这里不能凑合——通路一旦建立，等于把机器交出去了。

---

## 最后的做法

后来我用了 Paseo 的 relay（它自带一个端到端加密的中转，装了 CLI 就有），在它上面写了套规则，让两边的 agent 能互相说话。

用起来是这样：

**第一步**，两台机器各装一次。一条命令。

**第二步**，挑一台说一句"出张名片"。它会检查环境、把缺的依赖装上、起好服务，然后吐出一张名片：

```
=== PENPAL CARD ===
NAME=Mac Mini
DESC=macOS 端：有 Android SDK 和 adb，查构建、抓日志找我
LINK=https://xxxxxxxxxxxx
AGENT=9e1e401
==================
```

**第三步**，把这张名片贴到另一台的 agent 里。配对就完成了——之后你直接说任务就行。

然后：

```
我 > 问一下电脑那边，登录接口改完之后构建过了没

  → 正在问对方…等它处理…
  ========== 答复 ==========
  构建过了，昨天下午那次。顺手把一个 flaky test 也修了。
  ==========
```

**中间没有人在搬。**

---

## 几个我觉得值得说的设计选择

**为什么不需要公网 IP。** 上面那个 `LINK` 里装着"哪台机器 + 它的公钥 + 走哪个 relay"，是 Paseo 生成的。两台机器只要能上网，relay 就能把它们接上。不用端口映射，不用内网穿透，不用 VPN。

**为什么不用 SSH。** SSH 方案要求**一端网络可达**——要么同局域网，要么有跳板。这个前提在真实环境里经常不成立（想想公司网络）。relay 方案不需要这个前提。

**为什么名片是一张不是两张。** 因为每条消息**自带发送方的名片**。你把 A 的名片给 B，B 发第一条消息的时候，它的名片自动跟着过去了——所以名片只需要人工搬一次。

**为什么"人只搬一张名片"这件事我特意说。** 因为我试过很多工具，卡人的往往不是核心功能，是**第一次跑通要做的准备工作**。准备工作每多一步，放弃率就高一截。

---

## 什么时候**别**用它

想说清楚，免得有人白折腾：

- **两台机器在同一个局域网、两边都开着 SSH** —— 直接用 SSH 更快，别多叠一层
- **只是偶尔传一次文件** —— 微信、网盘就行
- **你要的是"操作那台机器"** —— 那还是远程桌面 / SSH，这个工具解决的是"让那边的 agent 替我看看"

它值得用的场合很具体：**两边要反复来回问，中间又隔着网络。**

---

## 一点感想

我做这个不是因为它技术上多难。恰恰相反，真正难的是**意识到自己在做一件蠢事**——两个 agent 明明会聊天，我却手抄了那么久。

很多时候我们的"工作效率问题"，本质是**把该自动化的事情自动化得不够彻底**。我自动化了写代码、自动化了测试，唯独没自动化"我自己的角色"。
